## 1. MVP: 低コントラスト箇所の 1:1 可視化

パネルで WCAG 2.0 / 2.1 / 2.2 と適合レベル A / AA / AAA を選択できるようにします。初期値は **WCAG 2.2・AA**。MVP の可視化は各バージョンに共通するテキストの 1.4.3（AA）と 1.4.6（AAA）を対象にします。A にはテキストのコントラスト達成基準がないため、この可視化は実行せず理由を示します。詳しい対応表は `docs/ARCHITECTURE.md` を参照してください。

- [x] バージョンとレベルの選択 UI、初期値 2.2・AA、選択条件を検査・結果に渡す型を実装する
- [x] 適合レベルを累積して扱い、A ではコントラスト検査を行わず、AA は 1.4.3、AAA は 1.4.3 と 1.4.6 を適用する
- [x] 相対輝度とコントラスト比の純粋関数を実装し、境界値・半透明色・同色でテストする
- [x] 実効背景色と表示中のテキスト色、文字サイズと太さを取得する。計測不能な場合は理由付きで「未判定」を返す
- [ ] AA の 4.5:1・3:1 と AAA の 7:1・4.5:1 を判定する。ちょうど閾値のケース、非表示、装飾、ロゴ、非アクティブ要素の扱いを検証する
- [x] 対象タブとの通信と必要最小限のサイト権限を実装する。権限拒否・保護ページで分かりやすい状態を表示する
- [x] パネルから可視化を開始・停止できるようにし、閾値未満のテキストだけ背景と同色にする
- [ ] 停止、DevTools の終了、ページ遷移、再実行時に変更を正確に解除する。元の inline style と `!important` を復元する
- [x] パネルに選択バージョン・レベル、問題件数、元の比率、適用基準と閾値、未判定件数と理由を表示する
- [x] 選択条件を変えたら可視化と古い結果を解除し、新しい条件で再検査する
- [ ] fixture ページで通常/大きな文字、閾値前後、背景の継承、半透明、複数要素、動的更新を確認する
- [ ] Chromium で「可視化 ON → 問題箇所だけ 1:1 → OFF で元通り」を実機確認する

### MVP の完了条件

パネルの初期値は WCAG 2.2・AA で、2.0 / 2.1 / 2.2 と A / AA / AAA に切り替えられます。fixture で AA と AAA の各閾値に応じ、基準以上の文字は変わらず、基準未満の文字だけが背景と同じ色になります。A ではコントラスト可視化が実行されません。検査不能なケースは誤って合格/違反に分類されません。停止または選択変更で表示変更が戻り、対象サイト以外への権限を要求しません。結果に実行時の条件が表示され、`pnpm check` と `pnpm build` が通ります。

## 3. その他の WCAG チェック

自動検査は既存の [axe-core](https://github.com/dequelabs/axe-core) を第一候補として評価します。axe-core は WCAG バージョンとレベルのタグでルールを選べます（[API](https://github.com/dequelabs/axe-core/blob/develop/doc/API.md)）。導入前にライセンス、バンドルサイズ、DevTools 拡張での実行方法を確認します。自動検査だけで準拠全体を保証しません。

1. [ ] MVP の選択条件を各検査に適用し、バージョン固有の追加・削除を反映したルール一覧と根拠を表示する
2. [ ] 代替テキスト、フォームラベル、アクセシブルネームなど、修正箇所が明確な自動検査
3. [ ] 見出し・ランドマーク・言語・ARIA の自動検査と結果から Elements への移動
4. [ ] キーボード操作、フォーカス、リフローなど人手確認が必要な項目のチェックリスト
5. [ ] レポートの保存・比較。収集データとプライバシー方針を先に定義する

優先度は「開発中に直しやすいか」「自動判定の信頼性」「WCAG 上の影響」「実装コスト」で見直します。W3C の [WCAG 2.2 本文](https://www.w3.org/TR/wcag/)を規範的な根拠にします。
